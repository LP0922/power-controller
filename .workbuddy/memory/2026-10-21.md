## 闭环加粉接入（10:30 完成）：结论是"不重写算法，只写执行器适配层"

用户问：把算法变量改成当前设备，还是照原算法重写加粉控制？
**结论：都不对——算法层本来就是纯的（`dispensing_algorithm/core.py` 只有 dataclass + 观测→决策，无串口/无设备命令）。**
真正缺的是"决策 → 设备指令"的翻译层。老系统把它和 5000 行设备/状态机揉在 `scripts/device_control_server.py` 里（`_run_feedback_dispense` 约 1000 行），这才是难维护的根源。
所以新写 `control_panel/dispense_runner.py`（约 480 行），core.py/calibration.py **一行未改**。

**拓扑映射**：`FeedAction.frequency_hz` → QLS3600 频率；`duty_permyriad` → 方波占空比（/100 = %）；`window_position_units` → LA 推杆开度（老机器是 LA10 窗口，同一个"开度决定流量"的物理量）；天平 → mass_mg（1:1）。
老硬件的振动是 LA10 内置的（`la10.start_vibration(freq, duty)`），新硬件是独立信号源 + 独立推杆，所以频率/占空比/开度三个变量正好一一对应，只是"振幅 Vpp"是新增的手动参数（老系统没有）。

**Runner 结构**：`start(target, category, preset_id, amplitude_vpp, tail_mass_mg)` → 线程 preparing→running→settling→done/aborted。
- 参数来源全部走算法层：`validate_target_mass`(100–1000)、`interpolate_profile`(按目标插值速率档)、`powder_classification_params`(分类覆盖)、`DISPENSE_PRESETS`(种子 频率/占空/开度)。
- 采样 0.12s：天平 → `MassMotionEstimator` → `ContinuousFeedbackController.step` → 频率/占空比/推杆。
- 收尾：停振 → 等沉降（连续 5 样本极差≤2mg）→ 终值 → 推杆回起点 → 落盘 `control_panel/runs/dispense_*.json`（含全量采样与 0.5s 抽稀曲线）。

**四道兜底**：天平连续 5 次读不到（≈0.6s）中止；质量 > 目标+30mg 立即停；180s 超时；任何异常先关振动。
**互锁**：运行中所有手动操作（升降/推杆/搅拌启动/振动参数/开输出/天平去皮）在**路由层**统一拒绝（不能放进 hub 方法里——runner 自己也要调 rod_move）。急停会 `dispense.abort()` 先解除接管再停设备。

**离线仿真（假设备 + 一阶滞后被控对象，脚本已删）**：100mg→90.0 合格(-10)；中途停止→aborted 且振动关、推杆复位；天平失联→aborted 且 `estimated=True` 用最后已知值；k=8 巨流量→超重保护 aborted；500mg→487(-13)。
**已知偏差**：控制器预测停车按老机器拖尾标定，新硬件偏保守（-10~-13mg）。暴露 `tail_mass_mg`（= `fixed_tail_mass_mg`，0–50）当现场唯一旋钮：总偏轻就调大。真机首炉建议先用 100mg 试。

**为什么没复用老的两套**
- 老的 `dispensing_algorithm/calibration.py`（`execute_rate_search` / `execute_probe` / 网格实验）是按
  LA10 给的：reader 抽象里只有 frequency/duty/**window_position**，没有搅拌轴，且窗口是 LA10 内置振动的开度。
  新硬件已拆成"独立信号源 + 独立推杆 + 独立搅拌"，三轴不同源，直接套会写死错误假设。
- 老的 ILC（`docs/stage1-ilc-technical-proposal.md`：L0/L1 前馈表 + 每炉修正，限幅 5–10%）
  概念正好对得上，但实现和 5000 行 `device_control_server.py` 绑死。所以**只取思想**：
  前馈参数表 + 每炉自修正，重新实现在新链路上。

**新增 `control_panel/powder_feedforward.py`**
- 数据写进**老粉体库** `data/powder_library/<粉名>.json` 的 `feedforward_v2` 段（不另起库，7 种既有粉直接可用）。
  段内含：`signal`(freq/duty/amp)、`points`[(stir_rpm, rod_units) → rate_mg_s + cv/delta/startup]、
  `stage_stir_rpm`、`summary`、`correction`。
- 模型：同搅拌档内棒位分段线性；跨搅拌档线性插值；**不外推**（超范围取边界 + `achievable=False`）。
- `solve_rod(target_rate, stir)` 反解推杆；反解用 `target / correction`。
- `stage_stir` 推导：usable = 中位速率≥0.5 且 CV≤40% 的档 → coarse 取最高档、fine 取中位、precision 取最低可用档。
- `record_run(stages, accepted)` = 迷你 ILC：每段算 实测/查表预测 比值（查表用进段/出段棒位中点），
  取中位数做样本，EWMA α=0.35，限幅 0.5–1.8；**只在正常判停+合格+终值非估计时**更新，避免坏炉带歪表。
- `fit_controller_params()`：按该粉最高流量收缩步长（慢粉步长收到 1/4）。
- 名称解析 `_norm()`：去空白+小写，file stem / powder_id / powder_name 三种都能命中
  （玉米淀粉.json 里 powder_name 是"玉米淀粉 (Corn Starch)"）。

**新增 `control_panel/rate_calibration.py`（开环标定执行器）**
- 输入粉名 → 扫 (搅拌档 × 推杆开度)：每点 停振→**先动杆再取基线**→起振 T 秒→停振→沉降称重。
- 速率取**振动期间天平斜率**（去掉前 20% 与末尾 0.2s），不是"总重/时间"——后者把停车拖尾算进去会系统性偏大。
  另记 cv_pct（1s 窗口速率离散度）、startup_delay_s、delta_mg。
- 每点测完立刻落盘，中途停不丢数据。安全：单点增重 >2500mg 或瞬时速率 >150mg/s 立即停振中止；
  天平连续 5 次读不到中止；异常路径先关振动再停搅拌；结束推杆回原位。
- 默认网格 stir=[0,300,600] × rod=[150,300,450]，每点 6s；频率 10–80Hz（与控制器限幅一致）。

**改 `dispense_runner.py`（核心重写，约 800 行）**
- `StagePlan` + 显式三段策略（阈值按比例算，100–1000mg 通用）：
  coarse 0→55%、fine 55%→(目标−精修预留)、precision 最后 min(算法预留, 25%)≥8mg。
- 每段"不同的控制方式"落在**独立控制器参数**上：coarse 内部阈值 0.97–0.99（锁在粗加分支）、
  duty_step≥40、棒步 60、允许动杆；fine 阈值 0.01–0.03、duty_step≤40、棒步≤35、双通道；
  precision 阈值 0.01–0.03 + `precision_start_remaining=2×target`（强制精修分支+预测停车）、

- `stir` 全程由控制器管，收尾 `stir_stop("decel")` 缓停（转子上挂的粉会继续落，算进终值）。
- `_close_stage_log` 记录每段 start/end 质量、实际速率、`rod_final`（自修正用）。
- 结果 JSON 增加 `plan` / `stages` / `powder` / `calibrated` / `feedforward_update`。

`dispense_start` 支持 `powder` / `use_feedforward`；急停 `calib.abort`；

## 15:30 搅拌堵转保护锁存（flags=0x0D）清除 + 驱动错误应答被吞的 bug

现场：搅拌状态 0x3A 读到 13（0b1101）= 使能+堵转+堵转保护，转速 0，新指令被拒。

- 根因一：`ZDTEmm42Private.clear_stall()` 帧写成 `01 0E 00 6B`，手册 6.3.3 要求
  `地址 + 0x0E + 0x52 + 0x6B`（0x52 是这条指令的固定标志字节）。发错后驱动回 `01 00 EE 6B`。
- 根因二（更要紧）：`_exchange_once` 只校验首字节地址和尾字节 0x6B，**不校验状态码**，
  所以 `01 00 EE 6B`（错误命令）被当成成功返回 —— "清失败"和"清成功"在日志里长得一模一样。
- 修复：
  - `zdt_emm42_private.py`：加 `FLAG_CLEAR_STALL_BYTE=0x52`、`STATUS_OK=0x02`、
    `STATUS_CONDITION_FAILED=0xE2`、`STATUS_ERROR=0xEE`；`clear_stall()` 返回 bool
    （False = 条件不满足，即本来没触发）；`_exchange_once` 遇到 `addr 00 EE 6B` 抛 ProtocolError。
  - `app.py`：新增 `ActuatorHub.stir_clear_stall()`（读前状态 → 清 → 读后状态，日志两段对比）
    + 路由 `POST /api/stir/clear-stall`（走 manual 包装，加粉运行中拒绝）。
  - `index.html`：搅拌卡片加「解除堵转保护」按钮，成功/仍锁存分别提示。
- 实测：直接驱动 `01 0E 52 6B` → flags 13 → **3**（使能+到位），堵转/保护位清零；服务重启后
  走接口复验 before/after 都是 3、cleared=True。**未做任何转动测试**（推杆 282 / 升降 905·906 / 振动关）。
